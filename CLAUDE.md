## Pièges connus (appris à la vérification du lot 2)

- Écrire les scripts de patch avec l’outil d’écriture de fichiers : les heredocs shell écrasent les barres obliques inverses.
- `ConfirmDialog` garde le contenu d’une boîte fermée dans le document : deux boîtes sur une page ne doivent jamais partager un `id`.
- Les tableaux réactifs de Vue ne passent pas par `structuredClone` : copier la charge d’une commande via `useMutation` (copie profonde déjà fournie).
- Tests e2e : pas d’ancre `^` dans `getByText` sur un texte de gabarit Vue précédé d’un saut de ligne (espace en tête) ; `context.request` doit envoyer `Origin` et `Referer` pour que Sanctum reconnaisse la session ; un numéro de téléphone par spec (la détection de ressemblance bloque la création sinon) ; pour changer de compte, quitter la page (`about:blank`) avant d’effacer les cookies ; `setInputFiles` par chemin échoue si le chemin contient « ’ » : passer un tampon (`{ name, mimeType, buffer }`) ; le serveur e2e tourne avec `EEO_MAX_CLOCK_SKEW=2` (une action proche d’une révocation passe en revue pendant la tolérance) ; sur la CI, le calcul SHA-256 de Web Crypto est asynchrone hors du fil principal (tests unitaires de finalisation : empreinte déterministe) ; sur la CI la base e2e est PARTAGÉE entre les parcours (la liste du jour contient les brouillons des autres) : limiter les assertions à la carte ou à la ligne de son patient, jamais « aucun bouton sur la page » ; une reprise de la CI (`retries: 1`) retrouve la base de la première tentative : un patient et un numéro par essai (`testInfo.retry`, noms sans ressemblance) ; avant de cliquer sur « Enregistrer l’arrivée », attendre que le formulaire ait pris le motif (la note du contrôle de paiement apparaît), sinon le clic se perd.
- L’archive de livraison doit contenir `database/schema_catalog.json` et `database/05_integrity_checks.sql` (lus à l’exécution) ; `build-release.sh` le vérifie.
- Pint et Prettier : appliquer Prettier à tout le dépôt après un lot de modifications de gabarits Vue (il peut ajouter une espace dans un `<summary>` ou un bouton ; contrôler les tests de texte exact).

- Tests e2e de poste (G2) : un parcours qui prépare un poste doit rendre ses ressources avant la fin (une seule caisse hors ligne principale, `FINANCIAL_DEVICE_ELSEWHERE`) ; tout parcours qui prépare un poste OU démarre son serveur (`startLaravelServer`) importe `test` de `./support/test` : sa fixture arrête aussi le serveur qu'un parcours tombé a laissé actif et sort le poste d'un parcours non réussi (échec, délai dépassé, interruption ; `retireDevices`, `tests/e2e/support/database.ts`) et `prepareThisDevice` retire d'abord un poste résiduel que le parcours ne connaît pas ; `isolation-postes.spec.ts` le garde (2026-11-11 : un échec isolé avait fait tomber huit autres parcours et leurs reprises). Deux onglets d'un même poste : le dernier déverrouillage reprend la main (D11) et le premier refuse ses écritures (`VAULT_SESSION_STALE`, message générique à l'écran) ; une facture du serveur ne se lit pas hors ligne (la payer depuis une page chargée EN LIGNE, ou facturer sur le poste). `zz-diagnostics-sql.spec.ts` doit rester le DERNIER fichier (ordre alphabétique) : il juge toute la base des parcours. Un `click()` sans élément attendait jusqu'au délai du parcours (15 minutes pour les parcours hors ligne, `finally` jamais exécuté) : `playwright.config.ts` fixe `actionTimeout` et `navigationTimeout` à 60 s ; un parcours qui relance un serveur pour un poste rouvert sans lui appelle d'abord `forgetServerSession` (`support/device.ts` : le cookie de session survit à la fermeture et la page se rattache seule au serveur revenu, relecture toutes les 30 s, puis le lien « Se connecter au serveur » disparaît). `startLaravelServer` refuse un port occupé par un serveur que le parcours n'a pas arrêté et REPREND celui qu'un processus de test tombé a laissé (registre `storage/framework/testing/e2e-servers/<port>.json`, garde dans `isolation-postes.spec.ts`) : un processus de test a déjà planté sans message (code 0xC0000409, poste à 0,7 Go de mémoire libre) en laissant son serveur PHP détaché, et la reprise doit pouvoir aboutir. Tout parcours qui prépare un poste le RESTITUE avant la fin (`releaseDevice`) : `offline-sync.spec.ts` ne le faisait pas et a fait échouer `profile-flow.spec.ts` dans la suite complète. Après « Se déconnecter » en session de préparation, l'écran de déverrouillage doit fonctionner sans rechargement (`vaultDetected`, `services/vault.ts`). Une assertion sur un COMPTE de lignes dépend de la base partagée : comparer avant et après le parcours (P04 : 15 coquilles cliniques en CI, 0 en local) et rejouer sur une base peuplée, dans la même invocation de Playwright (chaque invocation remet la base à zéro).
